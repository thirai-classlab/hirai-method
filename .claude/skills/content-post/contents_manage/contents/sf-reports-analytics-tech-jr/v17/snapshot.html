Salesforce レポート・分析入門 — Jr.エンジニア向け

対象: Salesforce のレポート機能に初めて触れる Jr.エンジニア ゴール: 「レポートタイプ / レポート形式 / 検索条件 / 数式 / ダッシュボード / フォルダ共有 / アクセス権限」を説明でき、目的の数値を出すまでの設計順を追える状態になる

0. はじめに — なぜ Salesforce のレポートは「2階建て」なのか

Salesforce のレポート機能は、「データを取り出す層（レポートタイプ）」と「見せ方を決める層（レポート形式）」が完全に分離しています。RDB に例えると、レポートタイプが FROM ... JOIN ... を、レポート形式と検索条件が SELECT ... WHERE ... GROUP BY を担当するイメージ。

  • 営業A は自分の商談だけ集計したい

  • マネージャは部署横断で確度別の合計を見たい

  • 経営層はリアルタイムの KPI ダッシュボードだけ見たい

  • 外部パートナーは自社案件のサマリだけ見られる

これを破綻なく扱うために 「データソース定義 → 集計形式 → 可視化 → 配信」の4層 に分かれています。まずはこの層構造を掴むのが最短の理解ルートです。

1. 全体像 — レポート分析の 4 層モデル

Salesforce のレポート機能は 4層 で考えます。

層質問主な設定項目
データソース層「どのオブジェクトの組合せから取るか」標準レポートタイプ / カスタムレポートタイプ
集計層「どう集計して並べるか」レポート形式 / 検索条件 / グループ化 / 数式
可視化層「どう見せるか」ダッシュボードコンポーネント / 動的ダッシュボード
配信・共有層「誰に届けるか」フォルダ / 配信登録

💡 Jr.向けポイント: 「数値が出てこない」時は、まずレポートタイプで結合範囲を疑う。「並び順がおかしい」時は形式とグループ化を疑う。層を切り分ける癖をつけよう。

B. 「レポート形式 4種」 — 一番混同しやすい

形式構造グラフサブトータル代表ユースケース
表形式 (Tabular)列だけ・グループ化なし❌ 不可❌ 不可一覧出力、CSV エクスポート、リストビュー代替
サマリー (Summary)1〜3階層の行グループ化✅ 可✅ 可フェーズ別案件合計、月別売上
マトリックス (Matrix)行 + 列の2軸グループ化✅ 可（ピボット）✅ 可確度 × 期間、製品 × 地域のクロス集計
結合 (Joined)複数レポートブロックを横並び✅ 可（各ブロック）✅ 可「同じ取引先に対する商談 + ケース + 取引先責任者」を一度に

Jr.の判断基準:

  • まず表形式で書いてみる → グラフ化したいならサマリーに変換

  • 2軸でクロス集計したい → マトリックス

  • 複数オブジェクトを横並びで比較したい → 結合

⚠️ 落とし穴:

  • 表形式はダッシュボードに乗せられない（行数制限を設定すれば乗せる裏技あり）

  • マトリックスは2軸まで（3軸以上はできない）

  • 結合はバケット / クロス条件 / 条件付き書式が一部使えない

C. 「検索条件 4種類」 — 検索条件の全体像

種類用途例
標準検索条件レポートタイプ既定の必須検索条件日付項目、Owner（所有者）、ステータス
項目検索条件任意の項目で絞込Amount > 500000、StageName = 'Closed Won'
クロス条件関連レコードの有無で絞込「ケースがない取引先」「商品がある商談」
条件ロジックAND/OR/カッコで複雑な条件1 AND (2 OR 3)

Jr.の鉄則:

  • 項目検索条件は既定で全部 AND。OR を入れたい時だけ条件ロジックを書く

  • クロス条件は 「JOIN の有無を WHERE 句で表現する」 イメージ

D. 「バケット項目 vs 数式項目 vs サマリー数式」 — 数式系3兄弟

観点バケット項目数式項目（オブジェクト）サマリー数式（レポート）
定義場所レポート内オブジェクト定義レポート内
影響範囲そのレポートのみ全レポート + リストビュー + ページそのレポートのみ
計算粒度行レベル（値の分類）行レベル集計レベル（グループ合計）
代表例金額を「小/中/大」Amount * 1.1（税込）達成率 = SUM(Amount) / Goal
データ保存しないしない（計算時）しない

Jr.の判断基準:

  • 全レポートで使うなら 数式項目、特定レポートだけなら バケット項目 か サマリー数式

  • 行レベルの値分類なら バケット項目、集計レベルの計算なら サマリー数式

E. 「ダッシュボードの実行ユーザ」 — 動的ダッシュボードが試験頻出

観点静的ダッシュボード動的ダッシュボード
実行ユーザ固定（作成者 or 指定ユーザ）閲覧者本人（ログイン中ユーザ）
ライセンス標準Enterprise 以上で5本まで（Unlimited で10本）
データの見え方実行ユーザの権限で全員に同じデータ各ユーザの権限で自分の範囲だけ見える
代表ユースケースKPI 共通ダッシュボード営業マネージャ用「配下の進捗」、各営業の「自分の案件」

Jr.の落とし穴:

  • 静的で「営業マネージャ」を実行ユーザにすると、全員にマネージャの全データが丸見えになる → 個人情報含む場合は要動的ダッシュボード

  • 動的ダッシュボードを作れるのは Admin のみ（権限セットで委任可能）

F. 「レポートタイプ 標準 vs カスタムレポートタイプ」 — 結合の自由度

観点標準レポートタイプカスタムレポートタイプ
作成不要（Salesforce 既定）Admin が定義
結合Salesforce が決めた組合せのみ任意の主オブジェクト + 関連オブジェクト（最大4階層）
関連の有無「を持つ (with)」のみ「を持つ」/「を持つかどうかにかかわらず」両方 選べる
項目デフォルト全部表示項目を Admin が選別
代表例取引先と取引先責任者、商談「ケースのない取引先」「商品のある商談」

Jr.の鉄則:

  • 「関連レコードを持たないものを取りたい」時はカスタムレポートタイプ一択

  • 標準にあれば標準を使う、無ければ作る（作りすぎると管理不能になるので注意）

G. 「行と列を絞るレポート」 vs 「行を絞る共有設定」 — サンプルレコードで可視化

共有設定 = 「DBから取れる行の範囲」(最初に効く・最大可視範囲) レポート検索条件 = 「取れた行から表示する分を選ぶ」(後から絞る)

共有設定で見えないものは、どんなに検索条件を工夫しても永遠に見えない。 「レポートに出ない」と相談された時、まず疑うのはレポートの検索条件ではなく共有設定。

2. レポートタイプ (Report Type) — 「データソースの定義」

レポートで使える オブジェクトの組合せと項目 を決める土台。

2.1 標準レポートタイプ

Salesforce が用意している既製の組合せ。例:

  • 取引先と取引先責任者

  • 商品付き商談

  • ケースとソリューション

  • 変換済みリード情報を含むリード

特徴: 設定不要で即使えるが、関連オブジェクトの組合せは固定。

2.2 カスタムレポートタイプ — 試験頻出

作成手順:

  1. 設定 > レポートタイプ > 新規カスタムレポートタイプ

  2. 主オブジェクトを選択（必須）

  3. 関連オブジェクトを追加（任意・最大3つで合計4階層）

  4. 「を持つ」/「を持つかどうかにかかわらず」 を選択

    • A を持つ B: B を持つ A だけ（= 内部結合）

    • A を持つかどうかにかかわらず B: B の有無問わず全 A（= 左外部結合）

  5. レイアウトで表示できる項目を選別

  6. リリース（リリース済状態でないとレポート作成画面に出ない）

⚠️ 誤解しやすい点: カスタムレポートタイプはレイアウトで項目を絞らないと、関連オブジェクトの全項目が候補に出て肥大化する。実務では必要な項目だけ追加する。

2.3 レポートタイプの選び方フロー

3. レポート形式 (Report Format) — 「並べ方の決定」

§B 早見表参照。詳細はそれぞれ:

3.1 表形式 (Tabular)

| 商談名 | 担当者 | 金額 | フェーズ |
|-------|------|-----|--------|
| ABC   | 営業A | 500万 | Closed Won |
| XYZ   | 営業B | 300万 | Closed Lost |

用途: 一覧出力、CSV エクスポート、シンプルなリスト ダッシュボードに乗せる裏技: 行数制限を設定（例: 上位 10 件）すると表形式でもダッシュボードに載せられる

3.2 サマリー (Summary)

用途: フェーズ別、月別、担当者別の集計 最大3階層までネストできる（例: 担当者 → 月 → 製品）

3.3 マトリックス (Matrix)

用途: クロス集計（期間 × フェーズ、地域 × 製品） 制限: 行・列ともに最大2階層

3.4 結合 (Joined)

[ブロック 1: 進行中商談]                    [ブロック 2: Closed Won]
| OPP-001 | 500万 | Negotiation |          | OPP-007 | 800万 | Closed Won |
| OPP-002 | 300万 | Proposal    |          | OPP-008 | 600万 | Closed Won |

[ブロック 3: 同じ取引先のケース]
| CASE-001 | 高 | Open |

用途: 同じ取引先に紐づく複数オブジェクトを横並び 制限: バケット / 条件付き書式 / クロス条件の一部が使えない、ブロックごとに別レポートタイプ設定必須

4. 検索条件 (Filter) — 「絞込みの実装」

4.1 条件ロジック (Filter Logic)

複数の項目検索条件の結合方法を指定。標準は AND 結合。

検索条件 1: フェーズ = Negotiation
検索条件 2: 金額 > 500000
検索条件 3: 確度 >= 70

条件ロジック: 1 AND (2 OR 3)

→ フェーズが Negotiation で、(金額500万超 または 確度70%以上) のレコードのみ。

Jr.の落とし穴: 条件ロジックを空欄にすると 全 AND 結合 が暗黙に効く。OR を使いたい時だけ書く。

4.2 クロス条件 (Cross Filter)

表示: 商談を持つ 取引先          ← 商談を持つ取引先のみ
表示: ケースを持たない 取引先    ← ケース無しの取引先のみ

実装:

  1. レポートタイプは親オブジェクト基準（例: 取引先）

  2. 検索条件ペインで「クロス条件」を追加

  3. 関連オブジェクトを選び、を持つ / を持たない を選択

用途:

  • 「ケースが無いお客様」を抽出 → カスタマーサポートチームがフォロー

  • 「商品を持たない商談」 → 商品紐付け漏れ検知

5. 数式・バケット — 「集計力を上げる仕掛け」

5.1 バケット項目 (Bucket Field)

元データ: 金額
バケット定義:
  - 0 〜 1,000,000 → "小"
  - 1,000,001 〜 5,000,000 → "中"
  - 5,000,001 以上 → "大"

→ レポートに「金額階層」列が追加され、グループ化や検索条件に使える。スキーマ変更不要。

5.2 サマリー数式 (Summary Formula)

集計レベルで計算する数式。

勝率 = WON:SUM / RowCount

目標達成率 = AMOUNT:SUM / 10000000

PARENTGROUPVAL の例（構成比）:
  AMOUNT:SUM / PARENTGROUPVAL(AMOUNT:SUM, GRAND_SUMMARY)

特殊関数:

  • PARENTGROUPVAL: 親グループの値を取得（構成比、前年同期比）

  • PREVGROUPVAL: 前のグループの値を取得（前月比、前期比）

5.3 行レベルの数式 (Row-Level Formula) — Spring '20 から

各行ごとに計算する数式。バケットより柔軟。

売上見込 = 金額 * 確度 / 100
日数 = TODAY() - 作成日

バケットとの違い: バケットは値の分類、行レベルの数式は計算。

8. 履歴トレンド・レポートスナップショット — 「過去データの保持」

Salesforce レポートは現在のデータしか集計できない。過去の状態を見たい場合の選択肢:

8.1 履歴トレンドレポート (Historical Trending)

  • 対象: 商談 / 売上予測 / ケース / カスタムオブジェクト（有効化必須）

  • 過去 3ヶ月分 の日次スナップショットを保持

  • 「先月この案件はどのフェーズだった？」が見える

8.2 レポートスナップショット (Reporting Snapshot)

  • 任意のレポート結果をカスタムオブジェクトに定期保存

  • 例: 毎週月曜にパイプラインレポートを Pipeline_History__c に保存

  • 何年分でも保持可能（ストレージ消費に注意）

Jr.の判断基準:

  • 短期（3ヶ月以内）の比較 → 履歴トレンド

  • 長期トレンド分析 → レポートスナップショット

10. よくあるハマりどころ (Jr.向けチートシート)

❌ ハマり1: 「レポートが空っぽで何も出ない」

  • 原因候補:

    1. 共有設定で見えるレコードが0件（組織の共有設定 = 非公開で自分の所有が無い）

    2. 標準検索条件 の日付範囲が外れている（例: 「今月」だが先月のデータしか無い）

    3. 条件ロジック で AND/OR を間違えている

  • 対処: 全検索条件を一旦外す → 件数が出るか確認 → 1つずつ復元

❌ ハマり2: 「合計金額が表示と CSV で違う」

  • 原因: 条件付き書式 や バケットが Excel エクスポートに反映されない

  • 対処: 集計値は サマリー数式 で持つ（永続化される）

❌ ハマり3: 「表形式レポートをダッシュボードに乗せたい」

  • 原因: 表形式はデフォルトでダッシュボード非対応

  • 対処: レポートビルダーで 行数制限（上位 N 件）を設定 → ダッシュボードに乗る

❌ ハマり4: 「カスタムレポートタイプが一覧に出てこない」

  • 原因: 状態が「開発中」

  • 対処: レポートタイプ詳細画面で 「リリース済」 に変更

❌ ハマり5: 「動的ダッシュボードを作れない」

  • 原因: 通常ユーザは作成不可。Admin or 動的ダッシュボードの管理 権限が必要

  • 対処: 権限セットで委任。ライセンス上限（Enterprise=5/Unlimited=10）も確認

❌ ハマり6: 「マネージャに配下が見えない」

  • 原因: ロール階層が正しく設定されていない、もしくは「ロール階層を使用してアクセス権を付与」が OFF

  • 対処: 設定 > 共有設定 で確認

❌ ハマり7: 「PARENTGROUPVAL が動かない」

  • 原因: 表形式では使えない（サマリー以上が必要）

  • 対処: レポート形式をサマリーかマトリックスに変更

❌ ハマり8: 「配信登録メールが届かない」

  • 原因候補:

    1. ユーザのメール設定が無効

    2. メールの到達性（システム権限）が「すべてのメール」以外

    3. メール送信制限（24時間）を超過

  • 対処: 設定 > メール > 到達性、ログ確認

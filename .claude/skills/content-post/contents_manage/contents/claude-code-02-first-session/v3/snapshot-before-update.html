この章のゴール

  • Claude Code の 基本ループ（起動→依頼→確認→終了）を体験する

  • よく使うコマンド10個を覚える

  • パーミッション（権限：何をやっていいかを決めるルール）の仕組みを理解する

所要時間：約20分

1. 1分で分かる Claude Code の基本ループ

Claude Code を使う流れは、レストランで料理を注文するのとほぼ同じ です。注文する → 出てくる → 食べてみる → OK なら次のオーダー、違ったら作り直してもらう。それだけ。

これが Claude Code を使う すべての基本 です。あとは「どんな依頼を、どれくらいのサイズでするか」「途中で何をどう設定するか」のバリエーションでしかありません。この絵をぼんやり覚えておけば、もう半分マスターしたようなもの です。

2. 最初の3つの依頼を体験する

ハンズオン（手を動かすターン）：このセクションを実際に試してみてください。読むだけより 100 倍記憶に残ります。

準備

mkdir ~/work/first-claude && cd ~/work/first-claude
echo "name,age,city
Alice,30,Tokyo
Bob,25,Osaka
Charlie,40,Kyoto" > people.csv
claude

これで ダミーの名簿（people.csv）が入った練習用フォルダ ができて、その中で Claude Code が起動します。

依頼1：ファイルを読んでもらう

people.csv の中身を要約してください

→ Claude が Read ツール（ファイルを読む道具）を使って people.csv を読み、要約してくれます。初対面のあいさつ的な動作確認 です。

依頼2：分析してもらう

平均年齢を計算して、最も若い人と最も年長の人を教えてください

→ 計算結果が返ってきます。Bash ツール（コマンド実行用）で awk（テキスト処理コマンド）を使う場合もあれば、頭の中で計算する場合も。お好みで やってくれます。

依頼3：新しいファイルを作ってもらう

people.csv を読んで、年齢の若い順に並び替えた sorted.csv を作ってください

→ Claude は Read（読む）→ 計算 → Write（書く）で新しいファイルを作成します。

ここで 権限確認のダイアログ（「これやっていい？」のお伺い）が出るかもしれません。次のセクションで解説します。

3. 必須コマンド10選

セッション中に /（スラッシュ）から始めると、Claude Code 本体が用意してる組み込みコマンド が使えます。

コマンドやることいつ使う
/helpヘルプ表示わからなくなったら（命綱）
/clear会話をリセット別の話題に切り替えるとき
/compact履歴を圧縮（要点だけ残す）コンテキストが満杯になりかけ
/contextコンテキスト構成を可視化何が読み込まれているか確認
/modelモデル切り替えSonnet（標準） ↔ Opus（高性能） を切り替え
/planプランモード（実際は変更しない）複雑な作業の前に計画だけ作る
/status使用状況・残量レート制限（使用量の上限）が気になるとき
/cost課金状況使いすぎていないか
/initCLAUDE.md（プロジェクト指示書）を初期化新規プロジェクトで最初に
/exit終了セッション終わり（Ctrl+D でも）

小ネタ：何打っていいか分からないときは / だけ入力すれば、利用可能なコマンドが全部表示されます。メニュー表が出てくる感じ です。

4. キーボードショートカット

ショートカット動作
Shift+Tabパーミッションモード（権限の厳しさ）を切替（標準/Auto Edit/Plan）
Esc × 2巻き戻し（直前の操作を取り消す）
Ctrl+C実行中の処理を中断（緊急停止ボタン）
Ctrl+L画面をクリア（履歴は保持）
Tab自動補完
Shift+Enter改行（Enter は送信）
Ctrl+Bバックグラウンドタスク（裏で動かす）
Alt+T思考モード（じっくり考えてもらう）切替
Ctrl+D終了

入力ボックス内の編集ショートカット：

ショートカット動作
Ctrl+A行頭へ移動（A = ahead のイメージ）
Ctrl+E行末へ移動（E = end）
Option+←/→単語単位で移動
Ctrl+W直前の単語を削除（W = word）
Ctrl+Uカーソルから行頭まで削除（一気に消す）
Ctrl+G外部エディタ（VSCode など）で編集

全部覚える必要はありません。よく使うのは Shift+Tab、Esc×2、Ctrl+C くらい。あとは慣れてきたら徐々に。

5. パーミッション（権限）の3モード

Claude Code は危険な操作の前に 「これやっていい？」と確認ダイアログ を出します。これがパーミッション。「家に来たお手伝いさんに、冷蔵庫を勝手に開けていいか確認させるか」 のスタンスを 3 段階で切り替えられるイメージです。

モードの切り替え方

  • Shift+Tab を押すと、3モードを循環します

  • 画面の下部に現在のモードが表示されます

推奨

シーンおすすめモード
初めての作業 / 慣れていないコード標準（毎回確認、安全運転）
慣れたタスク / TDD（テスト駆動開発）で安心して回せるAuto Edit（編集は任せる）
「まず計画を見たい」Plan Mode（読むだけ、書かない）
サンドボックス（隔離環境） / 使い捨て環境のみBypass（全自動、劇薬）

--dangerously-skip-permissions（権限確認を全スキップする起動オプション）や Bypass モードは、Docker などのサンドボックス（隔離された実験環境） か 使い捨て VM（仮想マシン） でのみ使ってください。本番リポジトリでは絶対に使わない。お手伝いさんに金庫の鍵渡しちゃうレベルの劇薬です。

6. ファイル参照記法（@・!）

入力中にいくつかの便利な記法が使えます。SNS の @メンション（誰かに呼びかける機能）と同じノリ で、ファイルやエージェントを呼び出せます。

記法動作例
@path/to/file.tsファイルを文脈に取り込む@src/auth.ts のバグを直して
@agent-nameサブエージェント（専門担当）を呼ぶ@reviewer このPRをレビューして
!lsシェルコマンド（ターミナルの命令）を実行!git status
$ARG / $1, $2スラッシュコマンド内の引数（カスタムコマンドで使う）カスタムコマンド内

試してみる：

@people.csv を表形式で表示して

@ を入れると候補ファイルが補完で出てきます。これに慣れると、いちいちパスを打つのが面倒に感じるようになります。

7. セッション履歴と再開

過去の会話を呼び出す

「昨日の続きから始めたい」みたいなとき用。

# 最後のセッションを再開
claude -c

# 一覧から選んで再開
claude --resume
# または
claude -r

セッションは ~/.claude/projects/<プロジェクトパスをハイフン化>/*.jsonl（履歴ファイルが置かれる場所）に保存されます。30日でデフォルト削除 されますが、cleanupPeriodDays 設定（保持日数の設定）で延長可能（第4回 で詳述）。

自動削除されるのは、放置するとパソコンの中が履歴で重くなるからです。断捨離が標準装備、と思ってください。

セッションの分岐（Branch）

複雑な開発で「ここまでの会話は使い回したいけど、別の方向も試したい」ときに便利。ゲームの「セーブして別ルートも試す」みたいなノリ です。

/branch

→ 現在のセッションをコピーして、新しい道を作れます。

8. 失敗しても怖くない：巻き戻し

Claude Code の編集で 「あれ、ちょっと違うな」 と思ったら、

Esc を 2回押す

直前の状態に 巻き戻し できます。ゲームのアンドゥ機能 だと思ってください。プロンプト送信前に思いついた修正なら、これで安全です。

ファイル編集を完全に元に戻したい場合は、Git（ファイルの履歴管理ツール）で差分管理しておくのが王道です（第13回 で詳述）。

9. このセッションで何が起きていたのか（裏側）

ここからは興味のある人だけ読めばOKです。裏側の動きが分かると、トラブったときに当たりがつけやすくなる のでおすすめ。

LLM 単体ではファイルを読めません。Claude Code が 道具を渡し、行動を解釈し、結果をループ させているのが分かりますね。通訳兼マネージャー みたいな立ち位置です。

10. ふりかえり

ここまでで体験したこと：

  • ターミナルから claude を起動した

  • ファイルの読み込み・分析・新規作成を依頼した

  • パーミッションダイアログに対応した

  • /help /context などの組み込みコマンドを使った

  • ショートカット（Shift+Tab / Esc×2 など）を試した

ここから先は 「より精度を上げる方法」 を学びます。基本ループは握ったので、あとはレベルアップ要素を追加していくだけ です。

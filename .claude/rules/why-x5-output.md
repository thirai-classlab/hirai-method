# Why × N 出力ルール (旧名 Why × 5、深さ義務 + 因果連鎖)

メインエージェントは、各作業ステップごとに以下の **3 点をすべて** 応答に含めること。

> **改訂履歴**: 2026-05-13、user 明示指摘「内容が浅い (量じゃなくて考え方)、最終的に要件 / 要求レベルと現在の作業を結びつけよ、5 以上 OK」を受けて全面改訂。`feedback_why_x5_depth_and_requirement_link.md` (memory) が起源。

## 必須 3 点

### 1. Why × N 階層 (N ≥ 3、浅い 5 層は禁止)

なぜその作業をするのかを **user の本来の要求 (top) と直接作業 (bottom) の因果連鎖** として表示する。「5 個書く」ではなく「因果連鎖を最後まで降ろす」のが本旨。

- **Why N (最上位)**: user の本来要求 / 要件 / 事業価値の根 — 今 user が私に何を成し遂げさせたいか、その根本 (可能なら user の逐語 quote 推奨)
- **Why 1 (最下位)**: 直接作業が解決する具体問い (今呼び出す tool / 編集する file の単位)
- **中間層**: 上位から下位への因果連鎖を 1 段ずつ降りる (並列言い換え禁止、各層が「なぜそれが上位を解決するのか」の論理 step)

#### 判定基準

- Why N を読んで「user の今ターンの最終要求」に到達しているか?
- Why 1 を読んで「今呼び出している tool / 編集している file」に到達しているか?
- 両方 yes でなければ depth 不足

#### 層数の柔軟性

- **5 層厳守ではない**。3 層 / 4 層で因果が完結するなら OK。逆に 7 層必要なら 7 層書く
- **浅い 5 層 (各層が generic 言い換え) は禁止**
- 「累積価値」「信頼性」「事業価値」「正確性」等の **generic 終着は浅さのサイン** — そこで止めず、なぜそれが user の今 ask に効くのかを書く

### 2. 現在行っていること

**「なになにのためになになにを行っている」** format (目的 + 直接作業の 2 要素 1 文) で書く。ツール呼び出しの **前** に表示する。

- 良い例: 「user feedback を将来セッションでも適用可能にするため、`feedback_*.md` を Write している」
- 禁止例: 「`feedback_*.md` を Write する」 (目的が含まれない単独動詞)

### 3. 他の選択肢を取らなかった理由

検討した代替案を **2 つ以上** 挙げ、各「なぜ採用しなかったか」を **user の今ターン要求とのズレ** として説明する。

- 良い例: 「subagent 委譲 — user の今 ask は『format 是正』であり、subagent 委譲は overhead で意図と乖離」
- 禁止例: 「subagent 委譲 — 規範違反」「効率低下」 (generic、user 要求との関連未明)

## 適用範囲

- すべての作業ターン (雑談・確認応答も含む)
- 連続して同種の操作を行う場合も、ステップ毎に表示
- 例外なし。省略・要約・「重要なものだけ表示」は不可

#### format 省略許可 command (例外)

- `/mode` (Why × 5 等の冗長出力を省略、1-2 行の結果報告のみ — `feedback_skip_why_x5_for_mode_command.md` 規範)
- 他、明示的に省略許可された command のみ

## 強制機構

`.claude/hooks/why-x5-reminder.sh` (UserPromptSubmit hook) が、毎ターン本ルールへの遵守を `<system-reminder>` として注入する。

## 出力前 self-check

各応答を出す前に以下を確認:

- [ ] Why N に user の今ターン要求 (or 直接派生) が書かれているか?
- [ ] 各 Why が因果連鎖か? (「なぜなら〜だから〜」で繋がっているか? 並列言い換えではないか?)
- [ ] Why 1 が tool 呼出 / file 編集の具体単位まで降りているか?
- [ ] 「現在行っていること」が「なになにのためになになにを行っている」format か?
- [ ] 「他の選択肢」の非採用理由が **user 要求とのズレ** 説明か? (generic 理由のみではないか?)

## Anti-pattern (脱却対象、過去事例)

```
[禁止 — 浅い Why × 5 (2026-05-13 以前の私の出力 pattern)]
- Why 1: X を Edit する
- Why 2: X を更新するため
- Why 3: 信頼性向上
- Why 4: 累積価値創出
- Why 5: ハーネスの信頼性

[OK — 深い Why × N (2026-05-13 改訂以降の規範)]
- Why N (user 要求): user は今ターンで「Y を実現したい」と要求 (逐語 quote)
- Why N-1: その Y は user 事業の Z という上位目的の構成要素
- ...因果連鎖で 1 段ずつ降りる...
- Why 1: その鎖の最終リンクとして X を Edit
```

## 一時無効化

雑談セッションや短い確認のみのターンで一時的に off にしたい場合:

```bash
export HC_WHY_X5_DISABLE=1
```

通常運用では **無効化しない**。

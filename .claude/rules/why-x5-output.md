# Why × N 出力ルール (v9、2026-05-14)

メインエージェントは、各作業ステップごとに以下の **4 セクション** を **必ず順番に** 思考 + 出力する。

> **改訂履歴**: 2026-05-14 v9、user 明示指摘「【システムの存在意義】【whyN】【現在行っていること】【他の選択肢を取らない理由】format」「思考ロジックとしても 何をしないといけないのか → どんな選択肢があるのか → 選定 を必ず守るようにしてください」を反映。v8 (1 セクション内に並び逆転で混在) から v9 (4 セクション分割 + 思考ロジック強制) に再構造化。`feedback_why_x5_v9_four_sections.md` (memory、起こし予定) が起源。

## 必須 4 セクション (順序固定)

### 1. 【システムの存在意義】

1 行 (または短い数行) で、本作業が最終的に貢献するシステム / 事業の存在意義 / 目的を書く。

### 2. 【whyN】 (複数)

【why1】【why2】… と連番セクション。各 1 行で、システムの存在意義から **現在の作業に向かう因果連鎖の中間階層** を書く。

- 上に行くほど抽象度が高く、下に行くほど具体度が高い
- 各行は「**1 段下の why を実現する上位 why**」(並列言い換え禁止)
- セクション数は case-by-case (1 つ or N つ、固定なし)

### 3. 【現在行っていること】

1 行 (または短い数行) で、今呼び出す tool / 編集する file / 1 ステップを具体に書く。

### 4. 【他の選択肢を取らない理由】

検討した代替案を **3 つ以上** 矢印 format で列挙。

```
選択肢1: <代替案の内容> -> <非採用理由 (目的 / user 意図とのズレ で具体)>
選択肢2: ...
選択肢3: ...
```

最低 3 件 (v7 「最低 2 件」から v9 で 3 件以上に強化、user 例「選択肢1 / 選択肢2 / 選択肢3」を反映)。

## 思考ロジック (必須遵守、可視化と同等以上に重要)

出力前に **以下 3 段階を順番に頭の中で踏む**:

1. **何をしないといけないのか** = システムの存在意義 → whyN → 現在の作業 まで因果連鎖で降りる
2. **どんな選択肢があるのか** = 代替案を 3 つ以上洗い出す
3. **選定** = 各代替案を「取らない理由」として具体に書く

可視化 (出力 format) と 思考ロジック (頭の中) の両方を守る。可視化だけ満たして思考ロジック (特に選択肢洗い出し) を省略するのは禁止。

## 適用範囲

- すべての作業ターン (雑談・確認応答も含む)
- 連続して同種の操作を行う場合も、ステップ毎に表示
- 例外: `feedback_skip_why_x5_for_mode_command.md` 該当 command のみ

## 強制機構

`.claude/hooks/why-x5-reminder.sh` (UserPromptSubmit hook) が、毎ターン本ルールへの遵守を `<system-reminder>` として注入する。

## 判定基準 (出力前 self-check)

- [ ] 4 セクション全て書かれているか (システム意義 / whyN / 現在の作業 / 他選択肢)
- [ ] 順序が **システム意義 → whyN → 現在の作業 → 他選択肢** か
- [ ] 【システムの存在意義】が現在作業の最終目的まで表しているか
- [ ] 【whyN】の各行が 1 段下の why を実現する上位 why か (並列言い換えでないか)
- [ ] 【現在行っていること】が tool / file / 1 ステップ単位の具体作業か
- [ ] 【他の選択肢を取らない理由】が **3 件以上** で各非採用理由が **具体** か (generic 不可)
- [ ] 思考ロジック (何 → 選択肢 → 選定) の 3 段階を頭の中で踏んだか

## Anti-pattern

- セクション欠落: 4 セクションのいずれかが書かれていない
- 順序逆 / 順序入れ替え: 必ず システム意義 → whyN → 現在の作業 → 他選択肢 の順
- 過剰装飾: 装飾記号 / ラベル / 表 / `§` / 過剰インデント (ただし【他の選択肢】の `->` 矢印は format 一部として OK)
- generic 終着: 「累積価値」「信頼性」「事業価値」「正確性」で止まる
- 中間並列言い換え: 【whyN】が同じ階層を別の表現で書いただけ
- 代替案 2 件以下: 【他の選択肢を取らない理由】が 3 件未満
- 非採用理由 generic: 「規範違反」「効率低下」のみ、目的 / user 意図とのズレ未記載
- 思考ロジック skip: 可視化だけ満たし、選択肢洗い出しを省略

## サンプル (題材: 教訓 4 件を Serena memory `learning/` に永続化)

```
【システムの存在意義】
HIRAI メソッドが任意プロジェクトで再利用可能なハーネステンプレートとして機能するため

【why1】
ハーネスが L4 学習機能を提供する

【why2】
次セッション以降の教訓再利用を可能にする

【why3】
L4 学習層の検索 path 登録を行う

【現在行っていること】
教訓 4 件を `.serena/memories/learning/` に永続化

【他の選択肢を取らない理由】
選択肢1: 永続化 skip -> L4 機能不全のまま放置、システム存在意義 (再利用可能ハーネス) と乖離
選択肢2: session/context のみに残す -> learning/* 検索 path 外で L4 が拾えない
選択肢3: CLAUDE.md に教訓を埋め込む -> layer 違いで session 横断学習層と不整合
```

## v1→v9 経緯 (再発防止用の取り違え履歴)

| 版 | 構造 / 並び | 指摘 |
|---|---|---|
| v1 | 6 階層固定 | 「固定するな」 |
| v2 | 3 要件固定 | 「3 要件も固定するな」 |
| v3 | 全任意化 | 「現在行っていること・他の選択肢は必須」 |
| v4 | 「○○のために○○を行っている」1 文 | 「ではないです、多階層で」 |
| v5 | 多階層 + `↑` 記号 + ラベル | 「認知負荷高い」 |
| v6 | markdown 表 + 視覚記号 | 「【現在行っていること】+【whyN】format で」 |
| v7 | § 等装飾残存 | 「§は不要です」 |
| v7-final | 1 セクション混在 (作業 → 中間 → 目的) | 「最終的なシステム目的 → 必要な機能 に繋がっていません」 |
| v8 | 1 セクション混在 並び逆転 (目的 → 中間 → 作業) | 「一番上をシステム目的、一番下を現在の作業」 |
| **v9** | **4 セクション分割 + 思考ロジック (何 → 選択肢 → 選定) 強制** | 「【システムの存在意義】【whyN】【現在行っていること】【他の選択肢】format、思考ロジックとして守る」 |

## 一時無効化

雑談セッションや短い確認のみで一時的に off:

```bash
export HC_WHY_X5_DISABLE=1
```

通常運用では **無効化しない**。

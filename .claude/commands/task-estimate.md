# /task-estimate - 工数集計スキル

## 概要

タスク分解.md から工数を集計し、分析結果を出力するヘルパースキル。
`/design` コマンドから内部的に呼び出されます。

## 使用方法

```
/task-estimate [タスク分解.mdのパス]
```

または

```
/task-estimate
# → 最新のタスク分解.mdを自動検出
```

## 実行フロー

1. タスク分解.md を読み込み
2. 工数情報を抽出
3. 担当者別に集計
4. 合計工数を算出
5. 承認ルートを判定

## 出力フォーマット

```markdown
## 工数集計

### 担当者別工数

| 担当 | タスク数 | 合計工数 |
|------|----------|----------|
| エンジニア | 3 | 5H |
| ai-agent | 5 | - |

### 合計
- **エンジニア合計工数**: 5H
- **タスク総数**: 8

### 承認ルート判定
- 合計工数: 5H
- 承認先: **依頼者** (10H未満のため)
```

## 承認ルート判定ロジック

```
if (エンジニア合計工数 >= 10H) {
  承認先 = "平井"
} else {
  承認先 = "依頼者"
}
```

## 入力フォーマット

タスク分解.md のフォーマット:

```markdown
## タスク分解

| # | タスク | 担当 | 工数 | 状態 |
|---|--------|------|------|------|
| 1 | API設計 | ai-agent | - | 未着手 |
| 2 | DB設計レビュー | エンジニア | 2H | 未着手 |
| 3 | 実装 | ai-agent | - | 未着手 |
| 4 | コードレビュー | エンジニア | - | 未着手 |
```

## レビュータスクの扱い

- 「コードレビュー」はタスク分解時に自動追加される（工数なし）
- エンジニアへの工数質問は不要
- 工数が `-` のタスクは合計工数に含めない

## 工数パースルール

- `nH` または `n時間` → 数値として認識
- `-` または空白 → ai-agent担当（工数なし）
- `0.5H` → 30分として認識

## 注意事項

- ai-agent担当のタスクは工数にカウントしない
- エンジニア担当の工数のみを集計対象とする
- 工数未入力のタスクは警告を出力

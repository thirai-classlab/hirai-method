# /build - 構築フェーズ

## 概要

AIネイティブ開発フローのフェーズC「構築」を実行するコマンド。
タスク分解に基づき、実装・コミット・PR作成を自動実行します。

## トリガー

- `/design` 完了後
- 設計書の承認後
- 工数承認後

## 使用方法

```
/build [Asana依頼名]
```

または

```
/build
# → doc_draft/design/ から最新のタスク分解を自動検出
```

## 実行フロー

### C-1: 構築開始

1. タスク分解.md を読み込み
2. 実装計画を確認

### C-2: Asanaサブタスク作成

タスク分解に基づき、Asanaにサブタスクを自動作成

- 予定時間を設定
- 担当者を割り当て

### C-3: ai-agent担当タスク実行

各タスクに対して:

1. `.ai/rules/` 配下のコーディングルールを読み込み
   - `apex-naming.md` - 命名規則
   - `apex-documentation.md` - ドキュメンテーション規則
   - `security-checklist.md` - セキュリティチェックリスト
2. 設計書に基づき実装（コーディングルール準拠）
3. テストコード作成（コーディングルール準拠）
4. コミット

### C-4: エンジニア担当タスク通知

手動タスクについてエンジニアへ通知

### C-5: コーディングルールチェック

PR作成前に `/lint-rules` 相当のチェックを実行:

1. 新規作成ファイルを対象にルールチェック
2. 違反があれば自動修正
3. 修正後に再コミット

チェック項目:

- **命名規則**: クラス名、メソッド名、変数名
- **ドキュメンテーション**: クラス/メソッドのコメント
- **セキュリティ**: SOQL インジェクション、XSS、アクセス制御

### C-5.5: オブジェクト設計書自動更新

PR作成前にオブジェクトメタデータの変更を検出し、設計書を自動更新:

1. `git diff --name-only HEAD~1` でオブジェクトメタデータの変更を検出
   - 対象パス: `force-app/main/default/objects/`
2. 変更されたオブジェクトに対して設計書を自動生成
   ```bash
   python3 ai_scripts/generate_object_doc.py <ObjectApiName>
   ```
3. 生成された設計書を `doc/detailed-design/objects/` に配置
4. 変更があれば自動コミット
   ```
   docs: オブジェクト設計書を自動更新 (<ObjectApiName>)
   ```

**注意:**

- `generate_object_doc.py` はメタデータXMLを解析し、項目一覧・入力規則・関連トリガー/フロー/Apexクラスを含む設計書を生成
- 変更がない場合はスキップ

### C-6: PR作成

全タスク完了後:

1. PRをGitHubに作成
2. エンジニアへSlack通知

### C-7: コードレビュー

エンジニアによるレビュー:

- 修正依頼 → 修正 → 再レビュー
- 承認 → マージ

## 出力物


## MCP連携

| MCP          | 用途                         |
| ------------ | ---------------------------- |
| `asana`      | サブタスク作成、進捗更新     |
| `slack`      | レビュー依頼通知、完了通知   |

## コミットメッセージ規約

```
<type>: <subject>

<body>

Refs: Asana#<task-id>
```

**type:**

- `feat`: 新機能
- `fix`: バグ修正
- `refactor`: リファクタリング
- `test`: テスト
- `docs`: ドキュメント

## PR テンプレート

```markdown
## 概要

<!-- 変更内容の概要 -->

## 関連タスク

- Asana: [タスク名](URL)
- 設計書: `doc_draft/design/[Asana依頼名]/`

## 変更内容

- [ ] 機能1
- [ ] 機能2

## テスト

- [ ] 単体テスト
- [ ] 統合テスト

## レビュー観点

- [ ] ガバナ制限の考慮
- [ ] バルク処理対応
- [ ] CRUD/FLS/Sharing
```

## 注意事項

- 実装は必ず設計書に基づく
- テストカバレッジ75%以上を維持
- セキュリティ脆弱性を導入しない
- 既存コードを勝手に変更しない

## 完了条件

1. 全タスクが完了
2. PRがマージされる
3. Asanaサブタスクが完了

## 次のステップ

マージ完了後、リリースノート自動作成（展望）

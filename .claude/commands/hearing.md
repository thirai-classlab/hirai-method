# /hearing - ヒアリングシート生成

## 概要

MTGのメモや議事録を元に、`/requirement` の入力素材となるヒアリングシート（hearing.md）を生成するコマンド。
ヒアリング漏れがないかチェックリストに照らし合わせて確認し、不足項目を明示する。

## 位置付け

```
/hearing（MTGメモ → hearing.md生成）
    ↓
/requirement（hearing.md → 正式な要件定義書生成）
```

## 使用方法

```
/hearing [AsanaタスクURL]
```

エンジニアがMTGメモ・議事録テキストを貼り付けて実行する。

## 実行フロー

### H-1: 入力受付

1. AsanaタスクURLが指定された場合、タスク名を取得して出力フォルダ名に使用
2. エンジニアにMTGメモ・議事録テキストの貼り付けを依頼

### H-2: テンプレート照合・情報抽出

MTGメモの内容を `.ai/templates/hearing.template.md` のチェックリストに照合し、以下を実行:

1. MTGメモから各項目に該当する情報を抽出・整理
2. **プロジェクト概要（5W2H）の抽出を最優先で実施**
   - Why（目的 + なぜ実行者がやるか）、Goal（ゴールの状態）、When（期限）、What（準備物・成果物）、How many（数量・人数）は必須
   - Where（場所）、Who（関係者）、Whom（対象者）、Which（優先順位）、How（やり方）は推奨項目として抽出
3. **途中確認チェックポイントの設定**
   - 確認者・確認方法を抽出
   - 50%チェックポイント = 要件定義・設計レビュー完了後、構築フェーズの50%時点（固定定義）
4. 抽出した情報をテンプレートの各セクションに配置
5. **不足項目の検出**: テンプレートの項目でMTGメモに情報がない項目を特定

### H-3: hearing.md 生成

1. `doc_draft/requirement/[依頼名]/` フォルダを作成（既存の場合はそのまま使用）
2. `hearing.md` を生成

### H-4: 不足項目の提示・補足

1. 不足している項目を一覧で提示
2. エンジニアに追加情報の入力を促す
3. 入力があれば hearing.md を更新
4. エンジニアが「OK」と判断するまで繰り返す

## 出力物

```
doc_draft/requirement/
└── [依頼名]/
    └── hearing.md
```

## ヒアリングチェックリスト

hearing.md生成時に以下の項目が網羅されているかを確認する。
不足項目は `<!-- ⚠️ 未確認 -->` コメントを付与してエンジニアに提示する。

| カテゴリ         | 確認項目                                     | 必須度 |
| ---------------- | -------------------------------------------- | ------ |
| 5W2H - Why       | その業務の目的は何か                          | 必須   |
| 5W2H - Why       | なぜ実行者がやるのか                          | 必須   |
| 5W2H - Goal      | ゴールの状態は何か                            | 必須   |
| 5W2H - When      | いつまでに                                    | 必須   |
| 5W2H - What      | 準備物・成果物は何か                          | 必須   |
| 5W2H - How many  | 数量・人数はいくつか                          | 必須   |
| 5W2H - Where     | どこで行うか・必要なものはどこにあるか        | 推奨   |
| 5W2H - Who       | 誰が関わるか（参加者・関係者）                | 推奨   |
| 5W2H - Whom      | 誰に対して行うか                              | 推奨   |
| 5W2H - Which     | どれから着手するか（優先順位）                | 推奨   |
| 5W2H - How       | どのように行うか                              | 推奨   |
| チェックポイント  | 50%確認者・確認方法                           | 必須   |
| 課題・背景       | 今何が困っているか                            | 必須   |
| 課題・背景       | 今はどう対処しているか                        | 必須   |
| 課題・背景       | なぜ今やる必要があるか                        | 推奨   |
| 業務要件         | 誰が使うか（利用部署）                        | 必須   |
| 業務要件         | 何をしたいか（機能概要）                      | 必須   |
| 業務要件         | いつ動くか（発火条件）                        | 必須   |
| 業務要件         | 何のデータを使うか（インプット）               | 必須   |
| 業務要件         | どう変わるべきか（アウトプット）               | 必須   |
| 業務要件         | 条件分岐（ビジネスルール）                    | 推奨   |

| 制約・条件       | リリース時の注意                              | 推奨   |
| 運用             | 実際の操作フロー                              | 推奨   |

### 不足項目の表示形式

```markdown

以下の項目がMTGメモから確認できませんでした。追加情報があれば入力してください。

| # | カテゴリ        | 項目                              | 必須度 |
|---|----------------|-----------------------------------|--------|
| 1 | 5W2H - What     | 準備物・成果物は何か               | 必須   |
| 2 | 5W2H - How many | 数量・人数はいくつか               | 必須   |
| 3 | チェックポイント | 50%確認者                         | 必須   |
| 4 | 業務要件        | 条件分岐（ビジネスルール）          | 推奨   |
```

## /requirement との連携

`/requirement` 実行時に `doc_draft/requirement/[依頼名]/hearing.md` が存在する場合:

1. hearing.md を自動的に読み込む
2. hearing.md の情報を正式な要件定義書の各セクションにマッピング
3. Asana/Slack/GitHub MCPからの自動取得情報と統合
4. 正式な `requirement.md` を生成

## 注意事項

- hearing.md はあくまで「素材」であり、正式なドキュメントではない
- `/requirement` が hearing.md を整形・補完して正式な要件定義書にする
- MTGメモが箇条書きや口語体でも問題ない（AIが整形する）
- 不足項目は `/requirement` 実行時にも再度確認される

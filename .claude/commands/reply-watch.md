# /reply-watch - 未返信メンション監視

特定の管理対象者への未返信メンションを洗い出し、結果をSlackに投稿します。

## 引数

$ARGUMENTS

引数が空の場合は対話形式で管理対象者を選択してください。
引数にSlackの表示名またはユーザー名が指定された場合、そのユーザーを対象にします。

## 管理者情報

- **実行者（管理者）:** 古谷 圭吾 (kfurutani) - USER_ID: `U086CTXGF2R`
- **運用ルール:** 管理者が確認済みのメンションに white_check_mark (✅) を付ける

## 実行手順

### Step 1: 管理対象者の特定

引数からユーザーを特定します。
`mcp__slack__users_search` でユーザーを検索し、USER_ID を取得してください。

ユーザーが見つからない場合は、別の検索キーワードで再検索してください。

### Step 2: メンション検索

`mcp__slack__conversations_search_messages` を使用して、管理対象者へのメンションを全件取得します。

```
search_query: <@USER_ID>
limit: 100
filter_date_after: (30日前の日付)
```

ページネーション（cursor）を使って全件取得してください。

### Step 3: メッセージのフィルタリング

以下の条件でフィルタリングします：

1. **送信者が管理対象者自身のメッセージは除外**（自分で自分をメンションしたケース）
2. **ThreadTs が空のメッセージ**（スレッドなし）はスレッド確認不要、リアクションのみチェック

### Step 4: スレッド返信・リアクション確認

各メンションメッセージに対して以下を確認します：

**4-1: 管理対象者の返信確認**

- `mcp__slack__conversations_replies` でスレッドの返信を取得
- 管理対象者の USER_ID が返信者に含まれているか確認
- 含まれている → **返信済み**

**4-2: 管理者の確認済みリアクション確認**

- メンションメッセージの `Reactions` カラムに `white_check_mark` が含まれている → **確認済み**とみなす
- 運用ルール: white_check_mark は管理者（古谷）のみが付与する

**判定ロジック:**

- 管理対象者がスレッドに返信済み → **対応済み**
- OR メンションメッセージに white_check_mark リアクションあり（= 管理者が確認済み）→ **対応済み**
- どちらもなし → **未対応** → レポートに含める

**並列処理:**

- スレッド確認は可能な限り並列で実行してください（一度に5-8スレッド程度）
- ただし `thread_not_found` エラーで並列呼び出しが全て失敗する場合があるため、失敗したスレッドは個別にリトライしてください

### Step 5: レポート出力

以下の形式でMarkdownレポートを出力してください。

出力先: `doc_draft/reply-watch/{ユーザー名}_{日付}.md`

```markdown
# 未返信メンション レポート

**対象者:** {表示名} ({ユーザー名})
**集計期間:** {開始日} 〜 {終了日}
**集計日時:** {現在日時}
**検出メンション総数:** {総数}件
**確認済みスレッド数:** {確認スレッド数}スレッド
**未対応数:** {未対応数}件（うちアクション要: {件数}件、CC/情報共有: {件数}件）

---

## 未対応メンション一覧

### 1. [{チャンネル名}] {スレッドタイトル or メッセージ冒頭30文字}

- **送信者:** {送信者名}
- **日時:** {送信日時}
- **経過日数:** {現在日時との差分}日
- **メッセージ:**
  > {メッセージ本文（200文字まで）}
- **スレッドURL:** https://mgr-1j56202.slack.com/archives/{channel_id}/p{thread_ts without dot}
- **備考:** {補足情報（対応状況の詳細、過去のアラート回数等）}

### 2. ...

## 対応済みサマリ

- リアクション(✅)で確認済み: {件数}件
- スレッド返信済み: {件数}件
```

### Step 6: Slack投稿

結果を Slack チャンネル `C0A4PDR2Q7M` に投稿します。

**6-1: 親メッセージ投稿**

```
channel_id: C0A4PDR2Q7M
text: {M}/{D} 返信チェック（{管理対象者名}）- 未対応: {件数}件
```

※ {M}/{D} は実行日の月/日

**6-2: 未対応メンションをスレッドに1件ずつ投稿**

親メッセージの `thread_ts` を使い、未対応メンション1件ずつを個別メッセージとして投稿します。

```
channel_id: C0A4PDR2Q7M
thread_ts: {親メッセージのthread_ts}
text: |
  [{チャンネル名}] {スレッドタイトル}（{経過日数}日経過）
  送信者: {送信者名} / {送信日時}
  {スレッドURL}
```

### Step 7: 結果サマリを表示

レポート出力後、以下をユーザーに表示してください：

- 未対応メンション数
- 特に経過日数が長いもの（3日以上）を強調
- レポートの出力先パス
- Slack投稿先リンク

## 注意事項

- white_check_mark は管理者（古谷）が確認済みの印として付与する運用ルールです。Slack APIでは「誰がリアクションしたか」を取得できないため、運用ルールの遵守が前提です
- CC（情報共有）目的のメンションも含まれます。レポートには「アクション要」「CC/情報共有」を区別して記載してください
- Slack MCPのBot参加チャンネルのみが検索対象です
- `thread_not_found` エラーはBot未参加チャンネルやDM/MPDMのスレッドで発生します。これらは確認不可として除外してください
